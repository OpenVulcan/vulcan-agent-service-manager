# 独立安装器与管理器实施计划

日期：2026 年 9 月 23 日。状态：已完成。

## 任务目标

在独立仓库完成可单独发布的五平台 Go 安装器与终端管理器。它负责安装及持续管理 Vulcan Agent Service，并支持 GitHub 官方源、可配置 HTTPS 国内镜像、主程序最新版发现、管理器自身版本检查和更新。优先使用主程序 v0.1.0 已发布的稳定命令及配置契约；只有证实功能无法实现时才调整主程序仓库。实现后开展循环代码审核和修复，直到连续五轮审核均没有发现问题。

## 技术选型与边界

- 管理器采用纯 Go，禁用 cgo，终端界面采用 Bubble Tea 第二代；网络、归档和摘要校验优先使用 Go 标准库。
- 管理器与主程序只通过已发布资产、版本化清单和稳定命令交互，不共享进程内类型或本地库。
- 脚本只下载、校验和启动管理器；管理器再下载完整主程序包。两个仓库独立维护版本。
- 主程序包与管理器包分别通过手动选择已有标签的工作流发布，标签推送不自动发布。
- 国内下载源提供 `https://gh-proxy.com/` 作为用户主动选择的代理预设，并支持自定义 HTTPS 地址；代理源的可用性以实际请求结果为准，失败时不自动改用其他源。
- “固定上下文长度”按用户确认的工具结果上限实现，映射至现有客户端预算配置；不修改模型上下文窗口。
- 用户确认首版以 GitHub 官方 Release API 提供的资产大小与 SHA-256 摘要为校验依据。镜像仅传输归档，不提供可信元数据；官方元数据不可达时拒绝安装，不引入独立签名密钥。
- 管理器自身的下载源与 PATH 所有权独立保存；卸载主程序不卸载管理器。

## 详细执行步骤

1. 核对两个仓库现状、版本、现有命令和发布清单。把主程序当前已支持的服务、技能、配置动作与需新增的机器接口逐项列出，建立兼容性版本表。
2. 建立 Go 模块、模块边界和统一错误模型。实现平台识别、配置与安装记录、命令行入口、结构化输出及 TUI/CLI 共用的应用服务层。
3. 实现发布源适配：固定标签和最新版发现、五平台精确资产解析、GitHub 与镜像 URL、下载进度、超时与取消、官方 API 大小和摘要校验及明确错误。分别处理主程序版本和管理器版本。
4. 实现 Windows 与 Unix 薄脚本，只下载对应管理器包并校验后启动。支持官方源、镜像基址及版本固定；覆盖管道执行时的终端输入和无交互环境。
5. 实现安全归档解压、安装前预检、同盘暂存、安装记录、配置初始化、服务安装/前台运行、PATH 管理、升级备份与回滚、显式接管既有安装、管理器自更新和卸载。
6. 实现 TUI 的首次安装向导、首页、服务、技能、配置与预算、下载源、诊断、更新和卸载页面；同时实现等价 CLI 命令。区分 ROOT 系统技能和 USER 技能，保留主动禁用状态。
7. 核对主程序 v0.1.0 的 `init`、服务、技能、配置和发布清单契约；管理器仅映射已证实字段与命令。对无法由现有契约实现的功能明确报错，再判断是否需要跨仓库变更。
8. 为管理器配置五平台原生构建、测试、独立打包、聚合校验、解包冒烟与手动发布工作流；验证发布后的真实下载路径。
9. 做单元、集成、模拟下载、故障注入与各平台原生测试，检查 SHA 不匹配、路径穿越、网络中断、更新回滚、服务权限和用户配置保留。
10. 完成后逐轮代码审核并自动修复。审核范围覆盖正确性、跨平台、事务与数据完整性、安全、用户流程和测试。每次出现问题都修复并重新验证，连续无问题轮数归零；连续五轮无问题后才结束目标。

## 验收标准

- 五个平台均有独立管理器资产；脚本不会下载完整主程序包；管理器安装后可以使用 `vasm` 打开。
- 用户能够明确选择 GitHub 或镜像，指定标签或发现最新版；每次展示最终版本与下载源，错误不触发静默换源。
- 主程序与管理器各自有版本检查、自更新或应用更新路径；Windows 正在运行的管理器可安全更新，失败保留旧版本。
- 首次安装和已有安装管理均覆盖 VMM、前台/服务、自启、PATH、系统/用户技能、配置查看与客户端预算；缺失的主程序契约明确报错，不猜测。
- 升级和卸载遵循文件归属边界，用户配置、技能和数据库保留或经明确选择后删除；故障可回滚到可运行状态。
- 五个平台构建后有对应平台原生冒烟证据；仅交叉编译不算通过。主程序和管理器的发布资产与官方摘要通过独立校验。
- 完成连续五轮零问题审核，保留每轮检查重点、发现、修复和验证记录。

## 执行变更总结

### 1. 核心修复与调整概述

独立管理器采用 Go 构建五平台版本；薄脚本只获取管理器，管理器依据 GitHub 官方发布元数据校验主程序或自身归档。TUI 先下载并校验主程序包，再询问配置并展示提交预览。安装、升级、卸载、同目录重装和自更新均有明确的状态边界和失败处理。连续五轮审核均未发现新增问题。

### 2. 📂文件变更清单

- 新增：`cmd/vasm/` 命令入口，`internal/` 下的发布、归档、安装、服务、配置、状态、PATH、自更新和 TUI 模块及对应测试。
- 新增：`scripts/install.ps1`、`scripts/install.sh`、`scripts/release.py`、`scripts/smoke.py`、打包测试和手动发布工作流。
- 新增：`go.mod`、`go.sum` 与 `docs/design/vasm-manager-design.md`。
- 修改：`README.md`，记录一键启动、管理命令、数据保留和发布方式。
- 删除：无。

### 3. 💻关键代码调整详情

- 发布客户端固定主程序和管理器仓库，官方 API 提供标签、大小及摘要；镜像只传输文件，下载与预取安装均重新校验 SHA-256。
- 安装器校验归档布局与主程序清单后在同盘暂存；升级与重装保留配置、日志、技能、状态、数据库及用户数据，失败时恢复旧目录。保留数据目录出现未知文件时拒绝覆盖。
- 本机服务安装失败时先核对注册项是否属于本次程序及运行根；仅清理确认归属的注册项。显式接管校验服务定义指向正确目录。
- TUI 与命令行共用管理动作，提供来源、版本、VMM、服务、技能、工具结果预算、PATH、诊断、更新、自更新和卸载入口；无终端时明确报错。
- 发布工作流只能手动选择已有标签，五个平台分别原生构建、测试和打包，聚合校验后发布。

### 4. ⚠️遗留问题与注意事项

- 无已知阻断问题。系统级原生服务安装仍需用户在目标机器以相应管理员权限执行；发布工作流验证了五平台原生程序、前台安装、预取、重装和配置流程，未在持续集成环境中创建需要提权的系统服务。
- 国内代理是用户主动选择的第三方传输端点；官方元数据不可用时安装会失败，不会自动降低校验要求。
